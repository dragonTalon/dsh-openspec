# @dragonTalon/dsh-openspec

> OpenSpec workflow skills and `/opsx-*` command aliases for DeepSeek Harness (DSH).

[![GitHub](https://img.shields.io/badge/GitHub-dragonTalon%2Fdsh--openspec-181717?logo=github)](https://github.com/dragonTalon/dsh-openspec)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![OpenSpec](https://img.shields.io/badge/OpenSpec-1.10.0-6e56cf)](https://github.com/Fission-AI/OpenSpec)

A [Cordis](https://github.com/cordiverse/cordis) plugin for DeepSeek Harness that registers the 12 canonical [OpenSpec](https://github.com/Fission-AI/OpenSpec) workflow skills under their kebab-case names — so `/openspec-new-change` works natively through DSH's user-invocation injection and the `skill` tool — plus the Claude-style `/opsx-<id>` command aliases as user-only skills that resolve to the canonical body.

- 12 canonical `openspec-*` skills (model- **and** user-invocable)
- 12 `/opsx-<id>` command aliases (user-only, content-identical to their canonical skill)
- No runtime state: skills are registered through DSH's skill registry, which owns uniqueness and lifecycle

## OpenSpec version

This package pins the OpenSpec workflow skills to **OpenSpec 1.10.0** ([`@fission-ai/openspec`](https://www.npmjs.com/package/@fission-ai/openspec), source: [`Fission-AI/OpenSpec`](https://github.com/Fission-AI/OpenSpec)).

The skill bodies are generated by [`scripts/sync-openspec-skills.mjs`](scripts/sync-openspec-skills.mjs) from the OpenSpec repository's `skills/*/SKILL.md` files. See [Syncing skills](#syncing-skills).

## Installation

The package targets DeepSeek Harness, which supplies its peer dependencies (`@deepseek-ai/cordis`, `@deepseek-ai/dsh-invariants`, `@deepseek-ai/dsh-skill`).

Install the plugin into a DSH profile from this repository:

```bash
dsh plugin --profile <name> add github:dragonTalon/dsh-openspec
```

Or add it to a plain Node project:

```bash
npm install github:dragonTalon/dsh-openspec
```

> `dsh plugin add` forwards to `pnpm add`, so any pnpm install spec works — `github:owner/repo`, `git+https://…`, a tarball, or a local path.
>
> Git installs build on install via the package's `prepare` script. `pnpm` blocks a git dependency's build script by default — if it refuses to run the build, add the package to `allowBuilds` in the profile's `pnpm-workspace.yaml` and re-run:
>
> ```yaml
> allowBuilds:
>   - "@dragonTalon/dsh-openspec"
> ```

## Usage

Once registered, both forms are available in DSH:

- Canonical: `/openspec-new-change`, `/openspec-apply-change`, …
- Aliases: `/opsx-new`, `/opsx-apply`, … (resolve to the same body)

### Configuration

```ts
import * as dshOpenspec from '@dragonTalon/dsh-openspec'

ctx.plugin(dshOpenspec, { aliases: false }) // disable the /opsx-* aliases
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `aliases` | `boolean` | `true` | Register the `/opsx-*` command aliases as user-only skills (`modelInvocable: false`). When `false`, only the 12 canonical `openspec-*` names are registered. |

## Development

```bash
npm install

npm run build   # tsc + tsdown → lib/
npm test        # vitest
```

### Syncing skills

`src/skills.ts` is auto-generated from a local OpenSpec checkout. Regenerate it when the upstream skills change:

```bash
npm run sync:skills         # regenerate src/skills.ts
npm run sync:skills:check   # CI check: exit non-zero when stale
```

The script reads `skills/*/SKILL.md` from an OpenSpec checkout — `~/Documents/github/OpenSpec` by default, overridable via `--openspec <path>` or the `OPENSPEC_REPO` environment variable.
